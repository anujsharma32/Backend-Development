4. Theory

PostgreSQL is a powerful, open-source object-relational database management system (ORDBMS) with a strong reputation for reliability, feature robustness, and performance:

  1. Schema Design and Constraints: - PRIMARY KEY: Uniquely identifies each record; PostgreSQL provides identity columns (GENERATED ALWAYS AS IDENTITY) conforming to SQL standards. - UNIQUE: Enforces that all values in a column are distinct. - CHECK: Validates that column data satisfies a boolean predicate (e.g., CHECK (age >= 0)). - FOREIGN KEY: Establishes referential integrity between tables, preventing orphan records.
  2. SQL Joins: - INNER JOIN: Returns rows that have matching values in both tables. - LEFT JOIN: Returns all rows from the left table, and the matched rows from the right table (with NULL if no match).
  3. Aggregate Functions: Aggregate functions calculate a single summary result from a set of values (e.g., AVG(grade), COUNT(*)). Grouping clauses (GROUP BY) partition the results into subsets for aggregate calculation.
  4. ACID Transactions: A transaction is a single logical unit of work that must satisfy four properties: - Atomicity: All operations succeed, or none do (ROLLBACK). - Consistency: The database moves from one valid state to another. - Isolation: Concurrent transactions do not interfere with each other. - Durability: Committed data is permanently saved (COMMIT).
  5. Database Security and Backups: - PostgreSQL controls access via Roles. Permissions on tables and schemas are assigned via GRANT SELECT, INSERT... TO <user> and stripped with REVOKE. - pg_dump extracts a PostgreSQL database into a script file or archive containing SQL commands to recreate the schema and restore all data.

10. Viva Questions

Q1: What is the difference between GENERATED ALWAYS AS IDENTITY and SERIAL in PostgreSQL?
Ans: GENERATED ALWAYS AS IDENTITY is the SQL standard-compliant way to create auto-incrementing integer columns in PostgreSQL 10+, whereas SERIAL is a legacy PostgreSQL pseudo-type that creates an implicit sequence.

Q2: What is the difference between INNER JOIN and LEFT OUTER JOIN?
Ans: INNER JOIN returns only records that have matching keys in both participating tables. LEFT OUTER JOIN returns all records from the left table regardless of whether a matching record exists in the right table (filling unmatched fields with NULL).

Q3: How does a ROLLBACK statement preserve database consistency?
Ans: ROLLBACK aborts the current transaction, undoing all pending changes made within the BEGIN block and returning the database to the state it was in before the transaction began.

Q4: What command-line tool is used to backup a PostgreSQL database to a file?
Ans: pg_dump is used to create logical backups of a PostgreSQL database in SQL text or custom archive format.
